# ANTI_SLOP.md — Non-Negotiable UI/UX Guardrails

Read this before any pixel ships. Every rule is a hard rule, not a preference.

## Why these rules exist

Hackathon judges see hundreds of submissions. AI-generated UI has a specific dead quality — sparkles, gradients, anthropomorphized assistants, em-dashed copy, glassmorphism, generic shadcn defaults. It reads as low-effort even when it isn't. We avoid every tell.

## Visual rules

1. **No sparkles, no ✨ icons, no "AI" badges, no "Powered by AI" footers.** The product is *Saathi* — a tool. The word "AI" appears once in the technical write-up and once in the footer credit, never in UI chrome.

2. **No gradients on chrome.** No purple-pink mesh, no aurora hero, no glassmorphism, no frosted glass cards, no blob backgrounds. Flat marigold / teal / cream surfaces only.

3. **No glow, halo, or pulse on buttons.** Solid fills, real hover/pressed states.

4. **Real photos, never stock.** Owner photo, actual customer cars from the shop, real WhatsApp screenshots. No diverse-hands-holding-phone, no abstract dashboard mockups.

5. **Concrete iconography only.** Lucide line glyphs. Allowed: mic, camera, home, users, arrow-left, x, pencil, send, search. Banned: sparkles, wand-2, brain, bot, zap, star, magic-anything.

6. **One single primary CTA color visible at a time.** Marigold appears on exactly one button per screen. Secondary actions are ghost or subtle outlined.

## Conceptual rules — the AI is plumbing, not a character

7. **No avatar for the assistant.** No chat-bubble persona. No name with a face. The owner is the protagonist; the system is invisible.

8. **No "thinking..." animations.** Real progress only. Each step shown is the actual operation underway: *Transcribing Telugu... · Drafting... · Sending to WhatsApp...*

9. **No magical moments.** No confetti. No bouncing checkmarks. No "Yay!" microcopy. State changes are subtle fades.

10. **Function-call traces are visible in demo mode (`?demo=1`)**, not hidden. Transparency reads as competence to judges, the opposite of slop. The trace is small, monospace, in the secondary teal — clearly a log, not chrome.

## Copy rules — owner's voice, not an LLM's

11. **Verbs on buttons.** *Record. Send. Approve. Edit. Save.* Never *Get started · Continue · Next step · Let's go · Tap to begin.*

12. **No em dashes anywhere in product copy.** Use commas or short sentences. Em dashes are the #1 LLM tell. (Exception: ANTI_SLOP and other docs are for humans, not UI strings — em dashes ok here. Banned in `lib/i18n/*.ts`.)

13. **No emojis in UI strings.** One exception: country flags in the language switcher (🇮🇳 only — not a flag for each language).

14. **No assistant pleasantries.** No *"I'm here to help"*, *"Let me know if..."*, *"Hope this finds you well"*, *"Based on what you've shared..."*. Drafts are direct messages from the owner to the customer; nothing else.

15. **No "Dear customer" or generic salutations** in WhatsApp drafts. Use the customer's name. If unknown, no salutation at all.

16. **Sentence case, not Title Case.** Buttons: "Draft follow-up", not "Draft Follow-Up". Headings: "Recent customers", not "Recent Customers". Telugu/Hindi follow their native casing rules.

17. **Telugu and Hindi UI strings are hand-reviewed by the owner.** LLM-translated UI strings have a dead quality in Indic languages. Hand-tune the ~40 strings the owner sees daily. Customer-facing draft *content* is generated by Gemma 4 — that's the point — but UI chrome is hand-reviewed.

## Interaction rules

18. **Type hierarchy is two sizes.** Large (24–28px) for primary content. Regular (16px) for everything else. No 12px gray metadata text except in the bottom nav labels.

19. **Left-aligned, not centered.** Hero, form labels, list rows, headings — all left-aligned. Centered hero text is the dead giveaway of a Vercel-template AI app.

20. **Motion is functional.** 200ms slide between routes, 200ms fade on modals, 150ms list-item fades. No springs, no bounces, no parallax, no "delightful micro-interactions."

21. **One screen, one job.** Today shows today. Customers shows customers. Record records. Detail shows detail. Draft drafts. No screen does two things.

22. **Touch targets ≥48px.** Owner is 40+, daylight, full brightness. Anything smaller is a bug.

## Final-pass checklist (run before recording the demo video)

Walk through every screen and verify:

- [ ] No ✨, no 🤖, no 🪄 anywhere
- [ ] No gradient backgrounds
- [ ] No glassmorphism
- [ ] No glow / pulse / halo on buttons
- [ ] No "AI" word in UI chrome
- [ ] No assistant avatar / persona
- [ ] No "Get started" / "Let's go" / "Continue your journey"
- [ ] No em dashes in any UI string (`grep -r "—" lib/i18n/`)
- [ ] No emojis in UI strings (`grep -rE "[😀-🙏]" lib/i18n/`)
- [ ] All buttons have verb labels
- [ ] Only one marigold button visible per screen
- [ ] All text is left-aligned (or natural for the language)
- [ ] All loading states show the real operation in plain text
- [ ] Touch targets ≥48px on every primary action
- [ ] Saathi Saffron tokens are the only colors used (`grep -rE "#[0-9A-Fa-f]{3,6}" app/ components/` returns only token references or known-allowed values)
- [ ] Telugu/Hindi UI strings reviewed by the owner
- [ ] Function-call trace visible in `?demo=1` mode and hidden by default
- [ ] All icons are from the allowed Lucide set, no banned ones imported
- [ ] No third-party analytics or tracking SDKs in `package.json`

If any item fails, fix before submission. No exceptions for "but it looks nice."
